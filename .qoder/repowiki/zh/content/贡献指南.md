## 简介

欢迎加入 IndexTTS 项目社区！我们致力于打造一个开放、协作和包容的环境，鼓励开发者、研究人员和用户共同推动文本转语音技术的发展。本贡献指南旨在为社区成员提供清晰的指引，帮助您以最有效的方式参与项目，无论是提交代码、报告问题还是改进文档。

IndexTTS 是一个工业级的零样本文本转语音系统，支持高情感表达和精确的语音合成控制。我们相信，通过社区的集体智慧，可以不断优化模型性能、提升用户体验并拓展应用场景。

## 代码贡献流程

为了确保代码质量和项目稳定性，我们制定了标准化的代码贡献流程。所有贡献者都应遵循以下步骤：

1. **Fork 仓库**：首先，在 GitHub 上 Fork `index-tts/index-tts` 仓库到您的个人账户。
2. **创建分支**：在本地克隆您的 Fork，并基于 `main` 分支创建一个新的功能或修复分支。分支命名应清晰描述其目的，例如 `feature/emotion-control` 或 `fix/punctuation-bug`。
3. **开发与测试**：在分支上进行代码修改。请确保您的代码符合项目的代码风格，并通过所有相关测试。
4. **提交更改**：使用清晰、简洁的提交信息提交您的更改。我们建议采用“动词+描述”的格式，例如 `fix: 修复中文标点处理错误` 或 `feat: 添加情感强度调节参数`。
5. **推送分支**：将您的分支推送到您的 Fork 仓库。
6. **创建 Pull Request (PR)**：在 GitHub 上从您的分支创建一个 Pull Request 到上游仓库的 `main` 分支。在 PR 描述中，请详细说明您所做的更改、解决的问题以及任何相关的上下文信息。

**代码审查标准**：
- **功能性**：代码是否正确实现了预期功能？
- **可读性**：代码是否清晰、易于理解？
- **性能**：代码是否有潜在的性能瓶颈？
- **兼容性**：代码是否与现有系统兼容，是否破坏了向后兼容性？
- **文档**：是否为新功能或修改提供了足够的文档说明？

## 问题报告指南

有效的错误报告是改进软件质量的关键。当您发现 Bug 时，请通过 GitHub Issues 提交报告。为了帮助我们快速定位和解决问题，请在报告中提供以下信息：

- **环境信息**：操作系统、Python 版本、PyTorch 版本以及 `uv` 或 `conda` 的版本。
- **复现步骤**：详细描述如何复现该问题，包括使用的命令、配置文件和输入数据。
- **预期行为**：您期望程序如何运行。
- **实际行为**：程序实际表现出的错误行为。
- **错误日志**：完整的错误堆栈跟踪（stack trace）或日志输出。
- **相关文件**：如果可能，请提供导致问题的音频文件或文本样本。

例如，一个高质量的 Bug 报告可能如下：
> **标题**：在 Windows 上使用 FP16 推理时出现 CUDA 错误
> **环境**：Windows 11, Python 3.11, PyTorch 2.8, uv 0.5.0
> **复现步骤**：
> 1. 运行 `uv run webui.py --fp16`
> 2. 在 WebUI 中输入文本并选择参考音频
> 3. 点击“生成”按钮
> **预期行为**：成功生成语音
> **实际行为**：程序崩溃，抛出 `CUDA error: invalid device ordinal`
> **错误日志**：[粘贴完整的错误日志]

## 新功能建议

我们非常欢迎社区成员提出新功能建议。在提交建议前，请先检查现有的 Issues 和 Pull Requests，以避免重复。您可以通过以下方式提出建议：

1. **创建 Issue**：在 GitHub 上创建一个新的 Issue，选择 "Feature request" 模板。
2. **详细描述**：清晰地描述您希望添加的功能，包括其用途、目标用户和预期效果。
3. **使用场景**：提供该功能可能的应用场景或示例。
4. **评估标准**：我们评估新功能采纳的标准包括：
   - **实用性**：该功能是否解决了实际问题？
   - **通用性**：该功能是否对大多数用户都有价值？
   - **实现难度**：开发该功能所需的工作量和技术挑战。
   - **与项目目标的一致性**：该功能是否符合 IndexTTS 的核心发展方向。

## 代码风格与测试要求

为了保持代码库的一致性和可维护性，我们遵循以下代码风格和测试要求：

- **代码风格**：遵循 PEP 8 指南。我们使用 `black` 和 `isort` 进行代码格式化。在提交代码前，请运行 `black .` 和 `isort .` 来格式化您的代码。
- **依赖管理**：项目使用 `uv` 作为包管理器。所有依赖项都应在 `pyproject.toml` 文件中声明。请勿直接修改 `.venv` 目录。
- **测试要求**：所有新功能都必须附带相应的单元测试。我们使用 `unittest` 框架。在提交 PR 前，请确保所有测试通过。您可以通过运行 `python -m unittest discover tests` 来执行测试套件。

## 社区氛围

我们致力于营造一个积极、尊重和包容的社区氛围。所有社区成员都应遵守以下准则：

- **尊重他人**：以礼貌和尊重的态度对待每一位成员。

- **遵守许可**：本项目遵循 Bilibili IndexTTS 许可证。所有贡献都将在此许可下发布。
